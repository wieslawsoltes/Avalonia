## 02: Notification allocation and ownership

AvaloniaProperty lazily retains immutable name-only INPC arguments, used by AvaloniaObject when an INPC listener exists. Typed Avalonia arguments remain per notification because they carry sender-specific old/new values and are observable reentrantly. Virtual overrides, property handlers, instance handlers and INPC listeners retain their ordering.

LightweightObservableBase already avoided snapshot rentals for zero through three observers. Larger snapshots now return cleared arrays in finally, including throwing callbacks. Publication still follows the captured subscription order outside the lock; an exception still interrupts it. FerroUiNotificationTests covers reuse, reentrancy, subscription mutation and exception recovery. No callback-skipping registry is introduced.

ResourceProvider.RaiseResourcesChanged reads its private owner field directly and is a small inlining candidate. The previous non-virtual property getter returned that same field. Owner snapshots, argument creation only when an owner exists, reentrant owner replacement and propagated exceptions remain unchanged; lifecycle virtual calls and OwnerChanged remain intact. See [resource publication](local-resource-write-overhead.md).

Inherited effective-value publication now uses the same property-owned immutable INPC arguments and avoids constructing arguments for an empty child collection. Sender/value arguments retain the original propagation mechanism. Tests verify repeated changes and clearing against the correct child senders; no notification is skipped for a present child.

## 03: Inheritance comparison pools and singleton sources

ValueStore.SetInheritanceParent resolves and compares ancestors before renting the dictionary. No-op ancestor returns no longer consume an unreleased rental; real general changes return rentals in finally. Existing property-ID matching, identity checks, local-value pruning and property-major order remain.

A null or terminal ancestor with exactly one inherited property can now be represented by one EffectiveValue reference. When both old/new sources satisfy that proof and concern the same property, both references are captured before changing the ancestor and the original notification routine runs without a comparison dictionary. Deeper chains, multiple inherited properties and differing property identities immediately use the general snapshot. The recognizer reads internal state only, not user callbacks or property values. Non-inherited local entries are allowed. See [the complete proof and eleven cases](single-property-inheritance.md).

FerroUiInheritanceTests continues testing general rental ownership and throwing callbacks using explicit two-property sources. SinglePropertyInheritanceTests compares exact optimized/general traces including reentrant reparenting, local pruning, equal values and detach/reattach, and verifies pool availability even inside a singleton callback. Object-major batching remains excluded because cross-object notification order is observable.

## 04: Live selectors and resource locations

Selector reuses immutable compound predecessor plans in original evaluation order, not match results or activators. A small single-node dispatch stays outside the compound-plan frame. A single non-container-query node returns its original match instead of building an AND around its only operand. Container queries, combinators and result-category conversions remain unchanged. TypeNameAndClassSelector reads its own constraint directly and calls Type.IsAssignableFrom. The earlier managed last-type memo was removed after repeated measurements exposed overhead. StyleKey remains a live read and inherited constraints preserve callback-sensitive repeated resolution. See [selector plans](selector-plans.md) and [dispatch repair](single-selector-regression.md).

ResourceDictionary caches weak supplying-dictionary locations or absence, never resource values. Found-null, non-shared deferred factories, custom providers and ancestor-host precedence remain live. Plain replacement retains a location and still notifies; structural changes advance the epoch before callbacks. Direct leaf probes and iterative last-merged tail calls make a full fallback cheaper without flattening a graph which callbacks may mutate. One inline string/theme entry avoids secondary-dictionary rewriting during revalidation and flushes dirty state before changing keys. The mirror remains within the original capacity.

A single-change shortcut requires a completed negative search, the same weak still-reachable dictionary/key, exactly one intervening epoch and a known plain insert/remove mutation. Normal winners are not assumed unique; deferred, unrelated, multi-epoch or graph changes still search. Opaque stored resource keys, arbitrary Type subclasses and opaque stored/requested/inherited theme keys disable location caching so arbitrary equality/hash callbacks cannot be frozen. Documentation: [lookup](resource-lookup.md), [live traversal](resource-traversal-regression.md), [inline locations](resource-inline-revalidation.md), [single-change proof](resource-single-change-proof.md), [theme safety](mutable-theme-key-safety.md).

Local hits stay outside the graph-cache resolver frame. The indexer has a small path only for a string request in a stable-key dictionary not yet used as a cache dependency. It combines its two plain-field flags without an extra short-circuit branch and accesses the lazy backing dictionary directly. Every other case retains callback-sensitive key tracking and dependency rechecks. Values commit before notifications; identical values still notify; deferred and structural changes retain invalidation. See [local reads](local-resource-dispatch.md), [string-write guard](resource-indexer-dispatch.md), [remaining dispatch overhead](local-resource-write-overhead.md).

## 05: Binding machinery

The general TemplateBindingExpression avoids redundant conversion for identical declared types without a converter. Compatible styled-property pairs use TypedTemplateBindingExpression<T> and IValueEntry<T>, removing boxing on normal publication through a generic property factory without runtime reflection. Direct/different/converter/sentinel/error-sensitive cases retain the original route. General-versus-typed traces verify clear, reparent, priority, reentrancy and two-way behavior. See [typed bindings](typed-template-bindings.md).

ReflectionBinding shares owned immutable grammar syntax per description and in a bounded cache for recurring paths. Observer nodes, converted index arguments, type resolution, name scopes and source selection remain fresh. Ownership prevents reentrant parsing from corrupting shared scratch syntax. See [reflection syntax](reflection-binding-path.md). Compiled paths already shared immutable descriptions; that is not new work. Allocation improvements do not establish elapsed-time improvement in every runtime mode; the latest Linux default measurements flag reflection-binding construction and are retained in the validation report.

## 06: Independent shaping, paired ownership and optional metrics

HarfBuzzTextShaper caches immutable short-run glyph snapshots with complete conservative keys and bounded retention. Returned pooled arrays are independent. Whole immutable strings without features are eligible; slices preserve surrounding context and mutable/ineligible input uses normal shaping without consuming adaptive policy probes. Cache-key work stays outside the native-shaping frame. Admission requires recent repeated use; hints expire on eligible bypasses as well as probes. Only actual hits reset miss backoff. Periodic bounded consecutive probes recover small cyclic sets otherwise missed by fixed-stride sampling. See [admission](shaping-admission.md), [expiry](shaping-admission-window.md), [recovery](bounded-cache-recovery.md), [ineligible inputs](uncacheable-shaping.md) and [dispatch](shaping-cache-dispatch.md).

Each pooled buffer's glyph-info and parallel glyph-ID arrays now use one PooledGlyphArray owner and reference count. Their lifetimes always coincide, so the former second owner/counter/finalizable reference and buffer field were redundant. Direct slices remain available for hot reads; splits and bidi views clone the one reference. Both arrays return only after the last alias is released. The existing RefCountable finalizer remains; constructor failure returns the first rental; caller-owned writable copies remain independent. Cluster-prefix storage is still separately shared and lazy. See [paired storage and its allocation/lifetime tests](paired-glyph-storage.md).

Admitted snapshots own value-only default-line metrics. Returned buffers carry optional state on the existing glyph reference rather than fields on every ShapedBuffer. Cache-hit construction allocates that reference directly; admission upgrades only an admitted buffer. Clone/CloneAs drop view-local state, while holder generation detects sibling mutation. Both ordinary and stateful paired references explicitly use the original base generic item type so CloneWithState retains its existing contract. Fresh unpublished buffers initialize glyph info and parallel IDs without redundant per-glyph invalidation; all public writes retain generation/cluster invalidation. See [optional metadata](shaping-allocation-regression.md).

Metrics reuse accepts only unchanged single runs with built-in default paragraph/run properties and an opted-in renderer. Exposed mutable GlyphRuns, complex paragraphs and custom cases use the original formatter; width-dependent overflow is recomputed. Cached metrics come from the original algorithm, not approximations. The shaper reads each native position once, retaining exact arithmetic order, tabs, offsets and clusters with fewer helper calls. See [metrics](default-line-metrics.md) and [earlier refinement](single-selector-regression.md).

## 07: Native geometry, fonts and demand-driven browser frames

SharedGlyphRunData leases geometry, relative bounds and retained blobs across recreated layouts. Full glyph records verify hash candidates; typeface/size and normalized rendering/hinting/baseline settings determine reuse. Wrapper-local borrowed caches keep warm lookup cheap; other users or cache eviction cannot dispose a leased blob. Owner first-blob storage is inline; the 18-state vector is lazy. Raw run views copy into native storage without managed builder-view wrappers. Admission/backoff is per font and includes expiry/cyclic recovery. See [shared glyphs](shared-native-glyphs.md), [native admission](native-glyph-admission-window.md) and [raw views](raw-native-blob-buffer.md).

GlyphRunImpl now stores its own borrowed primary blob/options inline as well, rather than allocating a TwoLevelCache object per wrapper. A second option lazily creates storage for three alternatives, retaining the prior insertion-order policy. Warm first-option hits remain lock-free; wrapper eviction never disposes shared blobs. Native geometry, hashing, equality and snapshot copying use transient spans for sealed ShapedBuffer and GlyphInfo arrays, with correct slice boundaries. Arbitrary IReadOnlyList callbacks remain on the general route. Seven tests cover allocation, 18 option states, sharing/disposal, LTR/RTL slices, pixels/bounds, mutation and user indexers. See [inline glyph dispatch](inline-glyph-dispatch.md).

Unique geometry uses a lazy configured-font pool with at most 16 retained fonts per used typeface. Each mutable SKFont is exclusively leased. Effective float size and normalized option state form the key; owner identity/simulations remain separate. Slot generations reject stale copied returns. Overflow is unretained. Owner disposal rejects new rentals, disposes idle fonts and defers active release until return; general CreateSKFont callers remain unpooled. Tests cover configurations, concurrency, capacity, ownership, raster equivalence and allocation. This trades bounded native retention for reduced construction/configuration, not free memory. See [font setup](native-font-setup-regression.md).

BrowserRenderTimer now respects the existing render loop's Tick-null sleep and subsequent Wakeup transitions. JavaScript cancels the idle requestAnimationFrame chain and forwards actual timestamps. Generation tokens make already-dispatched cancelled callbacks harmless; stop/restart during a callback cannot schedule duplicate chains. Worker transitions are coalesced asynchronous posts to the owning event-loop context, reading the latest callback. A missing or exact base SynchronizationContext retains safe polling because it cannot marshal to that JS realm; a throwing Post resets the queued flag before propagating so a later explicit update can retry.

Seven tests execute the actual TypeScript scheduler. Seven linked production-timer tests cover state/thread transitions, and five integration tests run against the actual DefaultRenderLoop with only JS/capability stubs. Continuous render work stays active, no-work tasks sleep, Wakeup during Render is retained, and remove/readd restarts cleanly. These tests do not replace an actual threaded-WASM/animation matrix. See [demand timer](browser-demand-timer.md) and [render-loop integration](browser-render-loop-integration.md).

Existing compositor dirty-subtree traversal and clipping remain unchanged. Exact native raster and browser light/dark/resource-change comparisons exercise output. Browser wheel/thumb/idle measurements keep diagnostics settings and distinguish task CPU/RAF from GPU presentation. The renderer decides whether work is needed; the browser adapter no longer polls after that decision says to sleep.

## 01, 08, 09: Applicability and evidence

C# has no Rust macro forwarding chain; Cargo/allocator/hasher flags are not managed library settings. Browser interpreter/AOT/named builds are application experiments rather than forced defaults. Compile-time counters disappear from ordinary build types/storage/call sites and are exercised by a separate instrumented workload.

Native measurement uses unchanged 26-scenario harness sources on exact refs, A/A calibration and five alternating baseline/head pairs. Browser A/B evidence uses unchanged real input, decoded pixels, visible resource restoration, readiness/task CPU/RAF/size data. Additional same-published-head A/A runs report variability and unequal workload states explicitly. Separate profiles cover wheel, thumb and idle in every render/deployment mode; they never replace unprofiled timings. See [calibration](counters-and-calibration.md), [browser evidence](browser-evidence.md) and [regression diagnostics](browser-regression-diagnostics.md).

The profile helper reconstructs absolute timestamps from signed adjacent deltas, stably sorts sample/node pairs and estimates forward intervals ending at recorded endTime. The pre-sample interval remains unattributed. It records reorder counts and versioned timing metadata while retaining raw profiles; it does not clamp negative deltas or hide malformed input. This corrects diagnostic accounting and is not an Avalonia speedup. See [timestamp repair](profile-timestamp-repair.md).

Passing correctness and heuristic screens do not establish an all-workload or physical-GPU speedup. Unfavorable runs/repeats, inconclusive classifications, historical attribution corrections and retention/deployment tradeoffs remain documented. The latest native Linux-default binding flags and positive macOS/browser measurements are not dismissed because other scenarios improved.
