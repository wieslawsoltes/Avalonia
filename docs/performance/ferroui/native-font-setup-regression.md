# Unique native glyphs: reuse configured fonts under exclusive leases

A unique geometry cannot benefit from a repeated-glyph cache. Its construction still created/configured an SKFont for bounds and another for its first native blob. Each configuration crosses the native boundary for hinting, edging, subpixel, baseline, linear metrics and simulation settings.

SkiaTypeface now lazily owns a bounded 16-slot configured-font pool used only by SharedGlyphRunData's read-only native operations. Effective float size and all 18 rendering/hinting/baseline states form the key; the owning typeface supplies font identity and simulations. Fonts are exclusively leased: another thread receives a different font while one is in use. An allocation-free value-type lease carries a slot generation so a stale copied lease cannot return a later borrow. Overflow and non-finite-size fonts are not retained. General CreateSKFont callers remain independent and unpooled.

Owner disposal rejects new rentals, disposes idle fonts and defers active-font release until those leases return. Native lifetime is supported by the pinned [Skia C binding](https://github.com/mono/skia/blob/v3.119.4/src/c/sk_font.cpp): sk_font_new_with_values constructs SkFont with sk_ref_sp(typeface), so an existing font owns a native reference independently of the managed typeface wrapper. Pool creation/configuration and disposal are serialized; no font is constructed while the owner native handle is being disposed. The pool retains no glyphs, runs, text or layout objects.

Tests cover exclusive and parallel rentals, stale copied leases, every effective option combination and multiple sizes, capacity overflow, owner disposal with active fonts, and zero managed allocation in warmed rentals. Existing raster comparisons against the original construction path and blob lifetime/eviction tests remain required. The unchanged complete unique-glyph scenario measures aggregate cost rather than assuming an isolated pooling win applies to the whole workload. The 16-font retention bound is not an exact byte-size estimate for native caches.
