# Design 04/05: shared resource-dictionary resolution caches

Every resource host's ordinary ResourceDictionary can now memoize resolution through its nested merged/theme dictionaries. Both implicit-theme lookup and dynamic-resource bindings use this path automatically. The cache is local to the dictionary, shared across elements consulting it, bounded to 128 short-string/type keys, and keyed separately by theme-variant identity. Lookup precedence remains local, requested/inherited theme, default theme, then merged dictionaries in reverse order.

Entries store the dictionary that supplied a key, not the returned value. Cache hits call `TryGetValue` on that dictionary, preserving `AddNotSharedDeferred` factory execution and null-as-a-found-value. Missing resources can be memoized too. Custom providers and dictionary subclass interface reimplementations remain dynamically probed; any result which would skip a custom probe is not cached.

All dictionary mutations, collection replacement/reordering, deferred materialization and individual bulk-set assignments invalidate a conservative global epoch before host/user callbacks. This also covers unowned nested dictionaries, where ordinary host notifications do not exist. Cached answers are discarded when the epoch changes during a lookup. Deferred construction suppresses memoization recursively so temporary reentrant misses are not retained. The existing ancestor-host walk remains live, preserving custom hosts and reparenting; caching an arbitrary ancestor result solely until a descendant notification would be incorrect during reentrant ancestor callbacks.

`FerroUiResourceLookupTests` covers local/merged/missing/null precedence, nested unowned mutations, reorder/replacement, variants/default fallback, non-shared factories, dynamic custom providers, reentrant host notifications, partial bulk updates and bounds. This completes dictionary graph memoization rather than assuming all extensible resource providers have immutable lookup semantics. Timing and render validation remain separate from these semantic checks.
